# 001. [bug] 빈 선택값을 제출하면 계획 입력 오류 화면 대신 500이 반환됨

번호: 로컬 #001
상태: Open
라벨: bug, good first issue
담당: ludwig-han (신규 백엔드 개발자)

## Background

계획 폼은 잘못된 입력을 저장하지 않고, 입력 내용을 유지한 채 오류를 알려줘야 한다. 빈 선택값도 서버 오류 없이 처리할 필요가 있다.

## Current behavior

기준 커밋: `db82c3d`. 로컬 H2, 조사 비활성화 상태에서 HTTP 요청으로 확인했다.

유효한 CSRF 토큰과 제목·날짜·첫 목표를 포함한 `POST /plans`에서 다음 값을 각각 빈 문자열로 제출하면 HTTP 500이 반환된다.

- `constraints.walking=`
- `anchors[0].timeSensitive=`

같은 조건에서 `anchors[0].kind=`는 HTTP 422를 반환한다. 정상 화면의 선택지를 그대로 사용했을 때 발생한다는 보고는 아니다.

## Expected behavior

유효하지 않은 선택값은 입력 오류로 처리하고, 사용자가 내용을 확인하고 다시 제출할 수 있어야 한다.

## Acceptance Criteria

- [ ] 위 두 조건에서 HTTP 422와 입력 오류 안내가 표시된다.
- [ ] 제목·날짜·목표 등 다른 유효한 입력은 오류 화면에 남는다.
- [ ] 생성과 권한 있는 수정 요청 모두에서 잘못된 입력이 DB에 반영되지 않는다.
- [ ] 정상 선택값 및 미정 선택은 기존처럼 저장된다.
- [ ] 생성·수정의 회귀 테스트가 있고 기존 테스트가 통과한다.
