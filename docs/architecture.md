# 구성 개요

기준: `db82c3d`. 현재 코드와 저장소 내 기록을 바탕으로 정리했다.

## 시스템 경계

하나의 Spring Boot 애플리케이션이 HTML 화면, 폼 요청, 정적 파일을 제공한다.
브라우저 JavaScript는 입력 보조와 같은 브라우저의 계획 목록을 담당한다.
계획 본문과 조사 기록은 관계형 DB에 저장한다. 기본 실행은 파일 H2, prod는 PostgreSQL이다.

서버에는 웹 요청·권한 처리, 계획 저장, 조사 실행 및 결과 표현 책임이 있다.
서로 다른 배포 서비스로 나뉘어 있지는 않다. 조사는 프로세스 내부 작업자에서 실행하며 외부 큐는 없다.

## 도메인

| 이름 | 책임 |
|---|---|
| Plan | 날짜·지역·목표·제약과 기존 메모를 보관하는 계획 |
| Anchor | 반드시 지키고 싶은 핵심 목표와 장소·시각 조건 |
| Priority | 함께 고려할 중요한 후보. 코드에는 Candidate라는 이름도 사용한다. |
| Guardrail / Transport | 도보·웨이팅·귀가 등의 제약과 참여자 이동 선호 |
| ResearchRun | 특정 계획 버전에 대한 조사 상태와 결과 |
| Backup | 조사 결과에 포함되는 조건부 대안 |

공개 조회와 수정 권한은 분리되어 있다. 참여자 출발지·귀가 도착지·기존 이동 메모·조사 결과는 계획자 화면에만 표시한다.
회원 계정이나 기기 간 계획 목록 동기화는 없다.

## 외부 연동과 요청

계획 저장 요청은 입력과 수정 권한을 확인한 뒤 DB에 반영하고 계획 화면으로 돌려보낸다.
공유 링크에서는 공개 범위의 계획만 표시한다.

조사 요청은 계획의 현재 입력을 대상으로 Gemini Interactions API와 Google Search grounding을 사용한다.
조사 결과와 출처는 저장 후 계획자 화면에서 확인한다. 계획이 수정되면 이전 결과는 재조사 필요로 표시한다.
조사 실패는 이미 저장된 계획의 조회·수정·공유를 막지 않는다.

현재 동시 조사 제어와 세션은 프로세스 내부에 있다. 다중 인스턴스 운영을 전제로 한 공유 제어는 없다.
